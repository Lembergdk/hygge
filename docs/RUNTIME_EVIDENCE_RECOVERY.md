# Runtime evidence and recovery repair

This change is stacked on the persistent-agent implementation in PR #79 (the work approved in the Codex chat “Review Hygge PR 75”), initially integrated at `891a290`. It reuses the one conversational reasoning loop, native tool results, owner-private ChatStore, asynchronous document mirror, existing mission queue, effect ledger and workspace registry. It introduces no classifier, new conversation engine, approval bypass or shared personal memory. The shared generic skill repository and its privacy checks are unchanged.

## Implemented behavior

- Logical artifacts can span 256 KiB RPC chunks, with an explicit 8 MiB logical-artifact quota. The container advertises protocol version 1. Old images continue to accept small writes; a large write to an old image fails explicitly with `ARTIFACT_PROTOCOL_UPGRADE_REQUIRED`.
- Begin/chunk/commit operations retain the existing HMAC owner, incarnation, generation, replay and lease checks. A transfer cannot continue in a replacement runtime. The manifest binds reference, byte count and SHA-256. Same-content retries are idempotent; a different payload cannot replace committed evidence. A complete verified file is published atomically, then included in the existing verified checkpoint path.
- Partial uploads stay in a reserved staging directory, outside capture coverage. Incomplete transfers block capture, are aborted on client failure, expire after five minutes without chunk activity, and are discarded on restart. A lost commit acknowledgement can be reconciled against the committed bytes. Limits remain on chunk, RPC, logical artifact and whole checkpoint size.
- Browser decisions normalize declared optional absence before approval/fingerprinting, hashing or dispatch. Page actions can have an empty target; control actions require a string target. Strict canonical JSON rejects unsupported types, sparse arrays, cycles and excessive depth. Invalid-payload diagnostics contain schema paths/types, not values or arbitrary property names. The exact historical Airtasker failing property has not been recovered; the demonstrated target-label failure is fixed and covered by a real mission-loop regression, without claiming that this proves the original site's root cause.
- Text and streaming Responses requests have a 120-second deadline. Container RPCs have a 120-second deadline; startup status probes use at most five seconds each within a 120-second startup loop. A timeout never means that an external effect was not applied.
- Queue exhaustion enters canonical runner recovery before the failed-job acknowledgement. An undispatched job fails visibly; existing effects or an orphan admission require review. A live local execution keeps its admission and may finish normally. Repeated and superseded deliveries cannot rewrite a newer job's task. Neither timestamps nor queue exhaustion release an admission or consume/replay a new approval.
- Task reads and native `list_tasks` expose delivery metadata separately from execution phase and progress timestamp: queued, waiting for workspace, starting browser, running, recovery or finished. These timestamps indicate actual phase changes, not a periodic heartbeat or proof of external progress.
- Canonical resting task outcomes enter chat history as deduplicated `task_outcome` system observations. The original native call keeps its single result (for example queued). A later success or recovery is available to subsequent reasoning without another `function_call_output` or another task dispatch. No model turn is started automatically by this event.

## Private documents

The private ChatDocument record still acknowledges a save immediately. Its workspace checkpoint remains separately pending until the existing background cleanup succeeds.

Document mirroring and deletion share persistent admission with browser missions. Background work fails fast while another operation owns the workspace and remains queued in ChatStore for retry. The root pins the runtime lineage across mutation and capture. The chat cleanup alarm and its provider-response cleanup behavior are preserved.

Each mirrored revision is immutable. Deletion supplies the generation/path-derived namespace and the highest deleted revision. The container persists a deletion watermark before removing matching versions. Delayed writes at or below that watermark fail, including after cold restore; a later revision can be written. This replaces PR #79's empty-byte overwrite cleanup. Evidence references cannot be deleted through the document API. The existing ChatStore generation/revision checks still govern mirror acknowledgement, correction and reset.

## Validation and operational limits

Regression coverage includes chunk boundaries; the observed 578,754-byte evidence size; multi-megabyte files; Unicode documents over 256 KiB; retry/conflict/order/corruption; incomplete transfer restart; cross-owner/stale-runtime rejection; local capture/cold restore; document deletion/recreation; concurrent mission/document admission; strict targetless actions; queue exhaustion with unresolved effects; live-run interleaving; and a singular queued native result followed by a separate task outcome.

Local Chromium, SQLite and object-store adapters exercise actual browser/profile bytes and protocol/checkpoint integrity. They do not establish Cloudflare deployment, populated-owner upgrade, site accessibility or full iOS acceptance.

The following work remains a release gate or follow-up, rather than a claim of completion in this PR:

1. **Populated-owner image upgrade/rollback:** current registry/checkpoint code requires an exact image digest. This PR deliberately does not relax that check or change Wrangler image pins. A new container image must be built and reviewed, and an explicit compatible-image migration must be implemented and verified before changing populated owners. Preserve an independent verified checkpoint and structured state, quiesce and fence the exact old browser/runtime, restore under a fresh generation, verify integrity/control state, and test rollback. Block if a final verified checkpoint is unavailable. Do not reset a workspace to make migration pass.
2. **Checkpoint scaling:** full captures/restores still accumulate bytes in memory and retain their existing 16 MiB/8,192-entry bounds and artifact-reference limits. Full screenshot evidence is still present in structured records. Streaming/deduplicated evidence and profile captures, explicit retention/quotas and large-profile acceptance remain separate work. No cookies, history or files are silently evicted.
3. **Orphan supervision:** the existing exact-runtime fencing recovery remains necessary for an orphan admission. This PR does not add a timer that steals ownership, a periodic progress heartbeat, or a new alarm-based queue watchdog. Queue retry/dead-letter handling and request deadlines improve observability but do not certify recovery from every infrastructure outage.
4. **Real runtime/site acceptance:** deploy only with separate environment authorization after the upgrade gate. Test the served Worker and immutable image together with two-owner isolation, cold recovery, fault injection, chat reconnect/compaction and document reset races. Then rerun public Pawshake/Airtasker checks and the capability suite in that exact runtime. The historical Contra stall's original cause remains unproven.
5. **Capability policy and identity:** this PR does not publish unverified site capability scores or treat Cloudflare Browser Run results as retained-container acceptance. Keep unknown/assisted/blocked states truthful in the common resolver. Identity-dependent signup, login, persistence and submission checks remain untested as requested; no personal profile or external submission is authorized here.

## Release state

A PR/green CI is source validation. Building/publishing a container, changing image pins, migrating populated owners, deploying a Worker, running staging/production acceptance, and TestFlight distribution are separate actions. None is performed by this repair PR. Preserve existing paused tasks and pending effects; reconcile through current observed evidence and the normal guarded APIs, never by clearing records or replaying uncertain work.
