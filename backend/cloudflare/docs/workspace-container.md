# Wave 2 colocated browser workspace

## Composition

`createContainerWorkspace({owner,container,image,rpcSecret,objects,namespaceId,providerWorkspaceId,getLease,now?})` returns `{provider,captureDriver,browser,attach,status,writeArtifact,listArtifacts}`. `container` is the current owner DO's `ctx.container`, not a namespace supplied by the model. Configure a private Hygge container binding and an immutable `registry/image@sha256:<64 hex>` image. Root keeps cloud/R2/vault/LLM keys; runtime receives only the owner-specific RPC secret. The owner-specific secret must be stable across trusted DO reconstruction and kept outside model/user access.

Use `new WorkspaceRegistry(storage, bridge.provider, now, {leaseDurationMs:300000})`; default lease duration remains60000ms, allowed1000..300000. After `registry.ensure`, call `bridge.attach(binding)` to verify the exact retained incarnation even on DO reconstruction. Expired idle leases are renewed only by `registry.reattachVerified(owner,owner,binding.revision,b=>bridge.attach(b))`, with a CAS recheck; no new generation/compute occurs. Broker issuance uses the new canonical `registry.readLease` afterward. A lost runtime or unknown provider state fails closed; this adapter does not invent evidence from an arbitrary absent instance.

`getLease()` must read the authoritative live registry and validate lease expiry/current authorization before every operation. External user/capability authentication remains root's responsibility. The factory verifies immutable owner, exact incarnation/generation and current lease. Internal HTTP/WS requests HMAC-bind owner, path, body, nonce, expiry and incarnation. Node rejects replay. Chromium receives a sanitized environment; it does not inherit HYGGE_RPC_SECRET or cloud credentials.

Initial `createSession(url,restore?,sessionId?)` accepts the effect-reserved opaque ID. Node records a blank reserved session before navigation; retrying that ID inspects the existing page without replaying navigation. Different original URL under the same ID rejects.

The returned browser implements the existing mission browser surface, keeps synchronous remote control-state cache, and pins an agent step's original epoch across intervening snapshots. Node uses one authoritative BrowserControl across every page in the owner's workspace. Human ownership in any session immediately stops agent admissions everywhere and waits for in-flight agent input before acknowledging takeover. Lazy reopen never decreases the global epoch; cold restore computes the maximum restored epoch before any page opens. Human pause survives close/lease expiry and only explicit handback clears it. An authenticated human reconnect may reopen its page while retaining pause; ordinary agent snapshot cannot navigate a closed session under someone else's human control. BrowserRun legacy cookie/localStorage state can be imported only into an empty profile at its matching origin; it never overwrites a current full profile.

## Save boundary

Write private evidence with `await bridge.writeArtifact(ref, Uint8Array)` (at most256KiB per item). `await bridge.status()` returns actual `filesystemRevision`, `browserProfileRevision`, `nextFilesystemRevision`, `nextBrowserProfileRevision`, `humanControlled`, `frozen` and internal owner/runtime identity. Build CaptureWrite using the **next** revisions and the current registry revision; materialize every declared evidence reference before requesting status. `listArtifacts()` includes owner-private evidence and completed download references.

Call the existing WorkspaceCaptureService with `bridge.captureDriver`. Capture refuses human ownership or in-flight downloads. It freezes admission, drains agent controls, cleanly closes Chromium (SQLite/WAL writers stopped), preserves live session IDs/epochs, and scans the private HOME tree. Freeze remains held across native reads, R2 upload/readback and recovery-head commit, then release unfreezes. The next browser operation lazily reopens the same profile/sessionIDs/URLs; same-incarnation capture retains control epoch. Cold restoration into a new incarnation increments restored control epochs.

Human control uses existing BrowserLive/BrowserControl code and the same state/frame/ack/takeControl/releaseControl/pointer/key/text protocol as the app. Capture does not silently seize human control. Live lease expiry freezes admission and closes Chromium; in-memory human pause is retained until explicit handback. Worker streams refresh authorization per incoming client message and close on expiry/failure. Browser frames are bounded and BrowserLive keeps one unacknowledged frame per client.

All files live beneath HOME=/workspace: Chromium profile, sessions, uploads/downloads and evidence. Capture omits only the owner marker and Chromium's machine/process-specific `SingletonLock`, `SingletonCookie`, `SingletonSocket`, and `RunningChromeVersion`; these are regenerated, not user artifacts. Files preserve permission modes; directories include empty/mode state; internal symlinks preserve targets. Unsafe/escaping/dangling links, file/symlink ancestors, duplicate paths, special files and unsupported metadata fail visibly. A consistent restore validates the complete manifest and bytes before replacing any uninitialized file tree; directories use temporary owner-writable modes then receive recorded modes.

Chunks are256KiB; current aggregate capture bound is **16MiB /8192 entries** to constrain in-memory Worker transport. This is an explicit interim transport bound, not silent eviction or a product storage allowance. Larger profiles/files fail closed; a streaming object/manifest implementation is required before supporting them. WorkspaceCaptureService defaults16MiB/512 entries; root may set maxEntries8192 to match the bridge. No large-profile acceptance is claimed.

The restore path independently verifies owner, manifest/content SHA-256, source incarnation/generation/sequence and image pin before sending bytes; Node rechecks metadata and each file hash before readiness. Image mismatch intentionally blocks; explicit compatible image-upgrade migration remains required. Successful status or queued requests alone cannot establish restored state. Cold restore must report the exact committed checkpointId.

## Provider boundary and image

The official [Durable Object Container API](https://developers.cloudflare.com/containers/api/durable-object-container/) provides image/env/labels/start, inspect, getTcpPort HTTP proxy, destroy and monitor. The factory verifies owner/hash/incarnation/generation labels and signed Node identity, waits for initialization/restore, and rechecks labels. Fence verifies the exact active incarnation then awaits destroy, monitor and inspect-null/running-false. `providerRequestIds` currently contains an internal operation trace reference: ctx.container does not expose a vendor receipt ID. Evidence is the awaited lifecycle/readback sequence, not that string or request acceptance.

Official `interceptOutboundHttp` supports IP/CIDR targets and registration before/after start. Every private/metadata/loopback CIDR deny installation is **awaited before start**; unsupported API/configuration rejects startup. See the [outbound interception API](https://developers.cloudflare.com/containers/api/durable-object-container/#interceptoutboundhttp). Real provider interception/TLS behavior still needs authorized staging acceptance; local synthetic tests deliberately allow loopback and do not prove cloud egress policy.

Build from backend/cloudflare: `docker build -f container/Dockerfile -t hygge-workspace:<revision> .`. Node package and lock pin puppeteer-core25.16.0 and ws8.22.1. The Dockerfile installs Debian Chromium, runs as unprivileged node with tini, and copies the existing BrowserLive sources. Deploy only the resulting immutable image digest. Root subsequently built a local Linux ARM64 image and verified Chromium full-profile capture/cold restore with networking disabled. A pinned digest of this image now runs in the deployed staging/production configs (see docs/workspace-v2-activation.md at the repo root); provider interception and runtime behavior are covered by the staged acceptance gates there, not by the local tests.

No Google Cloud SDK/client/resource is used. Any fallback must be a separate Hygge Google Cloud project within the allowed organization/billing relationship, with no Get BOB resource reuse; root's project-isolation policy remains mandatory.

Observed labels use one exact rule across snapshot and actions: aria-label, associated label, inner text, placeholder, name, then type, trimmed to60characters. Click/type/photo/upload require exactly one enabled exact match; ambiguity fails. Navigation accepts the existing agent target-URL convention (`value || target`).
