# Wave 2 owner-private skill integration

`createWorkspaceSkills` is a real trusted composition of owner SQLite candidates, C's canonical completion reader/durability verifier, HMAC attestation/service brokers and the shared D1 V2 transaction repository. Root constructs it inside the verified user's DO; runtimes never receive its secret, database or broker. No automatic endpoint, registry or provider activation occurs by importing it.

## Root wiring and run sequence

Construct with `{owner, persistence, authority, completions, sharedDatabase, registryConfig, secret, loadPrivateContext, maintainerAuthorize?, now?}`. `persistence` is C's existing `WorkspacePersistence`, `completions` implements `getCanonicalRunReceipt` and `verifyDurabilityCoverage`, and `authority` validates live owner capabilities. `loadPrivateContext(taskId)` reads trusted original task/profile values and original context artifact refs, not a model-supplied dictionary. Those values are snapshotted into owner-private DO SQLite and never enter shared requests. Required file artifact refs may be empty when all context is DO-resident; every actually referenced file/context artifact must be declared. C independently verifies the completion's browser/evidence/output dependencies regardless of this list.

1. Prefer `resolve(siteOrigin,outcome)` for validated active shared guidance. It returns `{skill,skillId,version,epoch,contentHash}`; `skill` is a legacy-compatible advisory `SharedSkill`, rendered solely from reviewed typed operations/templates. After C starts the canonical run and before the model receives this guidance, call `pinRunSkill(context,{taskId,runId,skillId})` to record immutable real usage. Later `usage(token,{skillId,receiptId})` requires the matching pin and successful canonical receipt, and updates confidence once. No model failure boolean is accepted; C currently represents mechanical failure as recoverable human attention, so automatic failure demotion awaits a canonical verified-failure contract. Quarantine remains available to authorized maintainers.
2. If no active shared skill exists, call `candidateForTask(siteOrigin,outcome)`. A validated private candidate returns `{candidateId,candidateBodyHash,revision,body}`. `body` is advice for the existing `skillCandidate` context only. Start C's run in `confirming` mode with that hash *before* mission execution. A published private candidate whose shared version is quarantined or invalid is not a fallback.

   Private fallback checks all shared publication rows with the same content hash, across owners and policy versions. Any inactive, quarantined, incompatible-policy or invalid matching publication blocks that body, even when this user never published it and has no local publication mapping. A shared database outage also blocks fallback; an unavailable lookup is never treated as proof that the body was unpublished. A globally unpublished body or exclusively validated active matches may remain an eligible private candidate.
3. On a successful confirming mission, C commits evidence/required recovery objects and an immutable matching receipt. Call `recordOutcome(context,{candidateId,receiptId})` with candidate's expected revision and stable request ID. It fetches canonical data, verifies ownership/hash/site/outcome/durability and counts each run once. Call `publishCandidate(token,candidateId)` after evidence accumulation; less than three distinct confirming successes holds publication. Old committed receipts remain valid after normal replacement. Lost publication responses can be retried: shared content/version deduplication prevents duplicate versions.
4. A first run without an existing candidate is `ordinary` with null candidate hash. After its canonical success receipt, call `captureTraceCandidate(context,{candidateId,receiptId,trace})`. The mapper holds the *whole* trajectory if any action lacks an exact reviewed representation, including failed/unknown actions, personalized/encoded URLs, private labels or untyped field values. A safe result is persisted privately. This initial ordinary run does not count toward three corroborating runs because it did not predeclare a candidate hash. The next three runs follow step 2.
5. Do not call legacy `recordSkillOutcome`/promotion in V2 mode. Arbitrary model `skillDraft` prose never enters this publisher. Keep legacy records for migration; do not mix old promotion with the V2 evidence path.

`recordCandidate(context,{candidateId,taskId,body})` is available for trusted structured-authoring adapters, but body still must pass strict registry/schema policy. Candidate body/hash are immutable; a revision requires a new candidate ID and new confirming evidence. `recordOutcome` uses candidate revision, independent of C task/checkpoint revisions. Retry the same request ID/payload to return the original result.

## Browser trace vocabulary

Exact reviewed public URL -> registered route ID; exact control ID -> inspect/click/fill/upload; exact field-set ID -> extract. No selector or label is heuristically generalized. Root should record the chosen private `valueRef` (not its resolved value) in V2 traces. Exact aliases supported: `draft.email -> profile.email`, `draft.name/displayName -> profile.displayName`, `draft.location -> profile.location`, `draft.searchTerms -> search.terms`, `draft.rate -> search.rate`, `draft.coverLetter -> application.coverLetter`. Existing approved V2 refs are also accepted. Unknown paths, arbitrary literals, and omitted type refs hold the candidate. A typical old browser trace lacking exact reviewed control/field refs may remain private even after a successful mission; this is deliberate coverage loss until reviewed extraction mappings exist.

## Consequential use and quarantine

`admit(token,{admissionId,skillId,version,epoch,taskId})` requires `skill.read` authority and a currently validated shared body. After C commits `dispatching` and before the actual tool, call `consume(token,{admissionId,effectId,taskId})`. It requires current `action.dispatch` authority and the exact owner/task effect in canonical dispatching state, then HMAC-binds private owner+effect+intent+lineage into an opaque identifier. Raw private IDs/hashes do not enter shared storage. Root's C action ticket remains the authority to execute; an idempotent successful consume response must not cause duplicate dispatch. Failed consumption stops the tool and uses C's trusted no-dispatch resolution path; ambiguous external effects are never assumed absent.

`quarantine(maintainerToken,{operationId,skillId,reason})` requires an explicit trusted backend maintainer callback. No callback means denial. Only reason enums are shared. The internal broker signs grants for exact checked arguments; it exposes no general signing capability. Quarantine ordering, policy/registry revalidation and mutation CAS remain provided by the V1 foundation.

## Registry, routes and legacy audit

`loadReviewedSkillRegistry` accepts only trusted reviewed config `{schemaVersion:1,sites:[...]}`. Site fields match `ReviewedSite`; unknown metadata and ambiguous origins reject. Absence produces an empty registry, so no guidance/promotion is enabled. There is no automatic crawling or personal-account learning of registry entries. Independent-public-evidence provenance must be established by trusted review tooling before configuration is loaded.

`handleWorkspaceSkillRequest` is a strict helper for root's already-authenticated owner-DO routing, not an internet authentication layer. Runtime mutation tokens arrive in `x-hygge-runtime-capability`; supplied context dictionaries/unknown keys reject. It offers candidate/outcome/trace-candidate/publish/pin/admit/consume/usage and generic read operations. There is no signing or public quarantine endpoint. Root must keep deployment inactive when required registry/key/capability/C/A adapters are unavailable, and must select owner before calling this helper.

`auditLegacySkillLibrary` uses a read-only query and returns a redacted dry-run hold/conversion plan for V1 rows. It never mutates V1/V2 or prints legacy bodies/IDs. Since V1 has arbitrary prose and missing private provenance, a passing regex is not permission to auto-convert or serve it in V2. Actual conversion/review/quarantine activation remains a separate explicit operation.

Local read-only command: `node --experimental-strip-types scripts/audit-legacy-skills.mjs <local.sqlite> [reviewed-registry.json]`. It opens SQLite with `readOnly:true`, has no remote credentials/bindings, and prints only the redacted plan. CLI regression verifies database bytes remain unchanged.

## Validation and limits

Focused tests use real private SQLite, real C completion transactions, real HMAC brokers and actual shared SQL batches. Durability transport/postcondition evidence in these tests is synthetic and explicitly trusted; real browser/provider restore remains later staging acceptance. No credentials, resources, deployment, migration or current user data were changed in this lane. No mathematical no-leak guarantee is implied.
